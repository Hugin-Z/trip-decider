# 宿主调用协议：减负三处与它们的判据

**起因**：首次真实宿主实测（Claude Desktop MCP，2026-08-03）两个事实：

* 宿主在**明确 DIRECT_PLAN 场景**下没有选用 trip-decider，自己 web search 排了
  行程，全程无出处断言；
* 被迫调用时，确认需求 / 提交证据反复试错十余次。

第一条是**描述**问题（认不出该用它），第二条是**协议**问题（用起来费劲）。
本文件管第二条；描述那条的守卫在
`tests/test_tool_descriptions_help_the_host_choose.py`。

---

## 原则

宿主是 AI 用户，不是人类用户。它不会读文档、不会记住上一轮的教训、也不会
「多试两次就熟了」——**每一次新对话都是第一次**。因此：

> 凡是宿主必须靠试才能填对的参数，都算缺陷。

减负不是加功能，是**把不该问的问题不问**。三条判据：

| 症状 | 处置 |
|---|---|
| 必填参数语义不明 | 改名，或给默认值，或从别的参数派生 |
| 多步序列不可发现 | 返回体带引导 |
| 同一信息要重复提交 | 服务端记住，幂等 |

---

## 减负 1：证据提交只问宿主知道的东西

内核的 `EvidenceItem.from_mapping` 要六个键。其中三个宿主根本不该被问：

| 键 | 此前 | 现在 | 理由 |
|---|---|---|---|
| `domain` | 必填 | **从 `action_id` 派生** | 内核随后就断言 `item.domain == action_id`，两者恒等。问两遍是纯重复，还给了填错的机会（D19） |
| `evidence_id` | 必填 | **服务端生成** | 只需在 run 内稳定。让宿主凭空发明一个字符串没有任何收益 |
| `status` | 必填 | **有 `value` 即 `sourced`** | 显式给了就尊重（报 missing / conflicting 时仍要显式写） |
| `sources` | 必填 | **仍必填** | 见下 |

`sources` **不补默认值，这是有意的**。来源是证据之所以成立的全部理由，服务端
代填就是伪造出处——那正好摧毁本服务与「自己检索」的唯一差别。缺了就报错，
并在错误里说清这是有意为之，否则宿主会以为是格式问题继续试。

显式给了 `domain` 但与 `action_id` 打架时**报错而不是取其一**：两个值都是宿主
写的，猜哪个对都可能猜反。

实现：`mcp_adapter._normalize_host_evidence`。它**不做校验**——校验的唯一出处
是 `agent_actions` 的提交门（railway 的必填集又从
`itinerary_planner.RAIL_EVENT_REQUIRED_TRAIN_FIELDS` 派生）。在这里抄一份校验
逻辑就又是两张表（D2），也就是上一轮那个 P0 的成因。

## 减负 2：每个返回体都带 `next_call`

宿主试错的一半花在猜「下一步调什么」上。检查点名（`NEED_INTENT_CONFIRMATION`
之类）说的是**现在在哪**，不是**接下来做什么**，两者之间的映射此前只存在于
代码里。

形状：

```json
{"reason": "<检查点名或 error_code>",
 "options": [{"kind": "...", "entrypoint": "<工具名>",
              "arguments": {"run_id": "..."}, "detail": "<一句话>"}]}
```

两条规矩：

1. **只写真的调得通的入口**（D14）。上一轮差点发一条声明了却调不通的出路——
   应用层放行了重试，宿主面的 `advance_trip_task` 却把 BLOCKED 当终局，
   `retry_comparison` 于是是假的。现在有用例守它。
2. **阻塞态优先透传 run 自己算出的 `recovery`**，不用按检查点名给的粗建议。
   两者都写就是两份可以不一致的指引（D19）。`recovery` 有两个来源（动作循环
   快照、`run.result`），语义相同，取到哪个用哪个。

错误也带：`TripMCPError` 把 `next_call` 既放结构化字段，也拼进 `str(self)`——
MCP 把异常渲染成文本，只放字段宿主看不见。

## 减负 3：重复确认幂等

此前第二次 `confirm_trip_intent` 抛「run is not awaiting confirmation」。

关键在于**宿主为什么会重复确认**：它拿到一个不熟悉的返回体，没看懂，保守地
又确认一次——然后收到一句听起来像出错的话，于是开始试别的调用。一次无害的
重复因此长成一串试错。

现在：已经确认过、又没带 `intent`，直接返回当前视图。

**带 `intent` 的重复调用不吞**：那是「改条件」，改不了必须说。把它一起吞掉
会让宿主以为条件改成功了——静默的错误比响亮的错误坏得多。

---

## 不在本轮范围

本轮只消除试错，不重设计协议。以下是**已识别但没动**的：

- `evidence` 仍是无 schema 的 `dict[str, Any]`。给它上结构化 schema 是正确
  方向，但那是改协议不是减负；
- `advance_trip_task` 语义仍然过载（启动比较 / 跑动作循环 / 重试阻塞）。
  描述里写清了三种语义，但没拆；
- 描述是中文、工具名是英文。混合语种没动。
