# trip-decider 使用说明

面向**使用者**，不是接手工程师。工程上下文在 `PLAN.md` 与 `docs/contracts/`。

一句话：你说什么时候走、几个人、多少预算，它先给出**真的到得了**的目的地候选，
定下之后排出从出发到返程的完整行程，每一条都带来源。**它不猜**——交通、票价、
时长都来自真实查询，查不到的东西它会说「不知道」，而不是编一个看起来合理的数字。

---

## 1. 准备

### 1.1 环境

需要仓库根目录下的 `.venv`（项目自带的 Python 环境）。检查：

```powershell
.\.venv\Scripts\python.exe --version
```

### 1.2 配置高德 key

跨城车次走 12306，**不需要 key**。目的地识别、景点、当地交通走高德 Web 服务，
**需要 key**。

去 [高德开放平台](https://lbs.amap.com/) 申请一个「Web 服务」类型的 key，然后
在启动前设进环境变量：

```powershell
$env:AMAP_WEB_SERVICE_KEY = "你的 key"
```

网页地图渲染另需两个（只影响地图显示，不影响行程计算）：

```powershell
$env:AMAP_JS_API_KEY        = "你的 JS key"
$env:AMAP_JS_SECURITY_CODE  = "你的安全密钥"
```

没配 `AMAP_WEB_SERVICE_KEY` 不会崩，但目的地与当地交通会一直是「未采集」，
行程排不出来。

### 1.3 验证环境能跑通

配好之后先跑一次冒烟，它用真实数据走一遍采集与编译：

```powershell
.\.venv\Scripts\python.exe scripts\smoke_live.py
```

每步会打印「预期」与实测。全部通过说明 key 和网络都没问题。

## 2. 两种用法

### 2.1 本地网页（推荐先用这个）

```powershell
.\scripts\run_product.ps1
```

浏览器打开 `http://127.0.0.1:8765/`。这是完整界面，行程、地图、修改重排都在里面。

### 2.2 挂进 Claude Desktop（MCP，**已实机验证**）

在 Claude Desktop 的 MCP 配置里加一个服务器，命令指向本仓库的 Python 与
`trip_decider.mcp_server`，并把 key 放进 `env`：

```json
{
  "mcpServers": {
    "trip-decider": {
      "command": "<repo>\\.venv\\Scripts\\python.exe",
      "args": [
        "-m", "trip_decider.mcp_server",
        "--runtime-root", "<repo>\\runtime\\sessions",
        "--with-web"
      ],
      "env": {
        "PYTHONPATH": "<repo>\\src",
        "TRIP_DECIDER_RUNTIME_ROOT": "<repo>\\runtime\\sessions",
        "AMAP_WEB_SERVICE_KEY": "你的 key"
      }
    }
  }
}
```

**2026-08-03 首次实机跑通**。挂上之后可以用自然语言建任务、看行程、改行程。
上面的 `--with-web` 会由**同一个 MCP 进程**同时提供网页
`http://127.0.0.1:8765/`；MCP 与网页因此共享同一份内存状态和运行时数据。

不要同时另开 `run_product.ps1` 指向同一个 `runtime/sessions/`。当前 store 的事务
边界是单进程；两个进程各持一份内存快照会互相覆盖。进程入口现在会对 runtime
加独占锁：重复启动会立即明确报“runtime 已被另一个进程占用”，不会再让两个
实例表面都活着、实际一直读旧状态。确实要同时开两套时，给它们配置不同的
`TRIP_DECIDER_RUNTIME_ROOT`。只使用 Claude、不需要网页时可以删掉 `--with-web`。

首次实测撞出两个会让任务卡死的缺陷，均已修复（P5 轮 3）：手工填写车次时按
提示填完仍然规划失败；目的地说得含糊时候选比较失败后任务无法继续。症状与现在
的处置见 [§6](#6-出了问题怎么看)。

## 3. 当前能用到什么程度（2026-08-03 实测）

**请先读这一节再决定怎么用。** 下面是拿真实数据跑出来的结论，不是设计意图。

| 用法 | 状态 |
|---|---|
| **你已经知道去哪**（说明确目的地） | ✅ **可用**。实测跑通：12306 真实车次票价、高德目的地与景点、编译出 23 个事件的逐日行程 |
| **你还不知道去哪**（让它推荐目的地） | ✅ **可用**（2026-08-04 起）。实测「从武汉出发、想找个山里安静的地方待两天」产出 2 个候选，各带实测往返车次与净可玩时长 |

**推荐目的地怎么用**：说出发地、时间、几个人、预算和偏好，**不用说目的地**。
系统会从候选池里挑，逐个**实查往返车次**，只把真的到得了的推给你。

一次比较大约 **20–40 秒**——因为它真的在查车次，不是在翻一张现成的表。

### 3.1 「有些地方被排除了」是功能，不是缺陷

候选列表下面会有一个**落选区**，列出被排除的地方和原因。这是有意的：

| 你看到的原因 | 意思 |
|---|---|
| 没查到往返车次 | 那个方向暂时没有可查的直达铁路 |
| 查询超时 | **我们没查完**，不是那地方去不了；可以重试 |
| 路上耗时过长 | 往返车程吃掉了太多行程窗（当前判据：路上不超过一半时间） |

**「查询超时」和「没查到车次」是两回事**，系统分开报——一个是我们的问题，
一个是现实的情况。落选区每条都能追问，不会有地方**悄悄消失**。

全部候选都被排除时，系统会**如实说「没有可行候选」并给放松建议**（比如延长
行程窗、换出发地），而不是硬凑一个到不了的地方给你。

**当前候选池是仓库自带的样例目录**（`examples/destination_catalog.json`，
28 个国内目的地）。你可以整份替换它——设环境变量
`TRIP_DECIDER_DESTINATION_POOL` 指向你自己的目录文件即可。

## 4. 一次完整使用

以「从武汉出发，去婺源待两天」为例——**明确目的地**的用法。

| # | 你做什么 | 预期看到什么 |
|---|---|---|
| 1 | 说出需求：出发地、时间、几个人、预算、节奏、交通偏好；目的地可给可不给 | 系统回一个待确认的意图；缺必填项会点名要（`pace` 与 `transport_preferences` 是必填） |
| 2 | 确认意图 | 任务开始跑，进入候选生成 |
| 3 | 等采集 | 逐步取回车次、目的地、景点；每项都带证据状态 |
| 4 | 选一个候选（没给目的地时） | 同一个任务继续，进入详细规划；落选区仍可查 |
| 5 | 等行程 | 逐日时间轴：跨城往返、当地交通、景点、餐食、住宿办理、缓冲 |
| 6 | 改一处约束（比如「第二天别那么赶」） | 生成**新版本**，旧版本仍在。新版本可用才会切过去 |

第 6 步是它和普通行程生成器的区别：改一处约束不是重新生成一份无关的行程，
是在同一个任务里出一个新版本，并且**新版本不可用时不会顶掉旧版本**。

## 4.1 核实别处来的行程

不排新行程，只核你手上这份。适用于：别的工具或某篇攻略给了车次，你想知道
它是不是真的。

逐条对照 12306 实查，每条给**三档**结论：

| 结论 | 意思 |
|---|---|
| 有据 | 查到了且对得上，附实查值与采集时间 |
| 冲突 | 查到了但对不上，附**两边**的值 |
| 查无实据 | 没查到 |

**「查无实据」不等于假**——可能是超出预售期、站名写法不同（12306 用车站全称）
或网络故障，返回体会说明该怎么办。把「没查到」说成「错」，是这个功能最容易犯
也最不该犯的错。

总评是**计数不是评分**：「5 条断言：3 条有据 / 1 条冲突 / 1 条查无实据，建议
出发前确认第 2、4 条」。哪条更要紧取决于你在乎什么，工具不替你定。

v0 只核铁路域（车次存在性、时刻、票价）。住宿、门票、当地交通未核验——
**没核不等于没问题**，报告里明写了这一点。

## 5. 看到 unknown / 待确认，是设计不是故障

系统对每一条事实都标两件事：**这个值有多可靠**，以及**它有多新**。

你会看到这些词：

| 你看到 | 意思 |
|---|---|
| 已核实 | 有真实来源，且在时效窗内。这是唯一「我有把握」的说法 |
| 需要重查 | 有来源，但超过时效窗了，正在或即将重新查 |
| 存在分歧 | 两个来源说的不一样，需要你选一个 |
| 不知道 | 没查到，或者根本没有数据源 |

**下面三样目前一定是「不知道」，这是已知的、有意的：**

- **住宿价格**——高德 POI 不返回价格，系统里没有房价数据源。行程会给你住宿
  **片区**和候选酒店的名字位置，但不会有价格，预算里也不含房费。
- **景点开放时间**
- **景点门票价格**

看到这三样是 unknown，不是系统坏了，是它**拒绝编数字**。这三样请自己在出行
前确认一次。

**「待确认具体酒店」**同理：没选具体酒店时，首末段交通按住宿片区或交通枢纽估算，
选定之后会细化。

## 6. 出了问题怎么看

- **行程一直排不出来**：多半是某个域没采到。界面会列出缺哪一项与下一步动作。
- **目的地/当地交通一直「未采集」**：`AMAP_WEB_SERVICE_KEY` 没配或配错。
- **车次查不到**：12306 只放售一定时间窗内的车次，日期太远就查不到。
- **运行停止并提示「系统内部错误」**：这是程序 bug，不是数据问题，运行记录里
  有异常类型。
- **手工填写车次被拒，说「缺少排程必需字段」**：按报错点名的键补齐再交。每个
  方向要五项：车次号、起点站、终点站、出发时刻、到达时刻。票价和余票是可选的，
  不填只会让费用显示为未知，不会挡住规划。
  手工填写动作自己带 `required_fields` 与 `optional_fields` 两份清单，以那两份
  为准。
- **任务停在 BLOCKED**：BLOCKED 状态自带 `recovery` 字段，逐条写着还能调哪个
  入口。常见两条：重新提交修正后的证据（任务就地续跑）、让动作循环重跑一轮。
- **候选比较失败（`GUIDED_COMPARISON_UNAVAILABLE`）**：任务不会就此作废。
  `recovery` 会给两条路——重试比较，或者跳过比较直接对你说的那个区域出方案
  （候选列表里那张标着「未比较」的卡）。**不需要重新描述目的地**。
- **当地交通只显示时长、不显示线路**：说明那一段高德返回的是驾车兜底而不是
  公交（该城该段没有公交方案）。有公交方案时会给出线路名、上下车站、换乘站、
  票价与步行距离；覆盖范围与已知缺口见
  [local-transit-coverage.md](contracts/local-transit-coverage.md)。

运行数据都在 `runtime/sessions/<run_id>/`，出问题时这个目录就是现场。

## 7. 当前不做的事

- **不订票、不订房。** 只做决策支持，给你可执行的行程和依据。
- **不猜。** 没有来源的数字不会出现。
- **不做消费级交互。** 修改重排目前靠改约束，不是拖拽。
