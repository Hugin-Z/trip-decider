# trip-decider 使用说明

面向**使用者**，不是接手工程师。工程上下文在 `PLAN.md` 与 `docs/contracts/`。

一句话：它从一个模糊的出游想法出发，先给出**现实可达**的目的地候选，等你定下
目的地之后，排出从出发到返程的完整行程。**它不猜。** 交通、票价、时长都来自
真实查询；查不到的东西它会说「不知道」，而不是编一个看起来合理的数字。

---

## 1. 准备

### 1.1 环境

需要仓库根目录下的 `.venv`（项目自带的 Python 环境）。检查：

```powershell
.\.venv\Scripts\python.exe --version
```

### 1.2 配置高德 key

跨城车次走 12306，**不需要 key**。目的地识别、景点、当地交通走高德 Web 服务，
**需要 key**。

去 [高德开放平台](https://lbs.amap.com/) 申请一个「Web 服务」类型的 key，然后
在启动前设进环境变量：

```powershell
$env:AMAP_WEB_SERVICE_KEY = "你的 key"
```

网页地图渲染另需两个（只影响地图显示，不影响行程计算）：

```powershell
$env:AMAP_JS_API_KEY        = "你的 JS key"
$env:AMAP_JS_SECURITY_CODE  = "你的安全密钥"
```

没配 `AMAP_WEB_SERVICE_KEY` 不会崩，但目的地与当地交通会一直是「未采集」，
行程排不出来。

### 1.3 验证环境能跑通

配好之后先跑一次冒烟，它用真实数据走一遍采集与编译：

```powershell
.\.venv\Scripts\python.exe scripts\smoke_live.py
```

每步会打印「预期」与实测。全部通过说明 key 和网络都没问题。

## 2. 两种用法

### 2.1 本地网页（推荐先用这个）

```powershell
.\scripts\run_product.ps1
```

浏览器打开 `http://127.0.0.1:8765/`。这是完整界面，行程、地图、修改重排都在里面。

### 2.2 挂进 Claude Desktop（MCP，**未实机验证**）

在 Claude Desktop 的 MCP 配置里加一个服务器，命令指向本仓库的 Python 与
`trip_decider.mcp_server`，并把 key 放进 `env`：

```json
{
  "mcpServers": {
    "trip-decider": {
      "command": "<repo>\\.venv\\Scripts\\python.exe",
      "args": ["-m", "trip_decider.mcp_server"],
      "env": {
        "PYTHONPATH": "<repo>\\src",
        "AMAP_WEB_SERVICE_KEY": "你的 key"
      }
    }
  }
}
```

**这段配置尚未在真实 Claude Desktop 里验证过**，是按 `mcp_server.main()` 的 stdio 入口写的；首次试用时请核对。挂上之后可以用自然语言建任务、看行程、改行程。
两种用法**共用同一份运行时数据**（`runtime/sessions/`）——网页里建的任务在
Claude 里看得到，反之亦然。

## 3. 当前能用到什么程度（2026-08-03 实测）

**请先读这一节再决定怎么用。** 下面是拿真实数据跑出来的结论，不是设计意图。

| 用法 | 状态 |
|---|---|
| **你已经知道去哪**（说明确目的地，如「武汉去婺源」） | ✅ **可用**。实测跑通：12306 真实车次票价、高德目的地与景点、编译出 23 个事件的逐日行程 |
| **你还不知道去哪**（让它推荐目的地） | ❌ **暂不可用**。见下 |

**「让它推荐目的地」目前不可用的原因**：实测输入「从武汉出发、想找个山里安静的
地方待两天」，两次运行给出的候选分别是「上海市」和「乌鲁木齐市 / 兰州市 /
北京市」——既不响应「山里安静」，也不考虑两天的往返可达性。候选排序目前只按
POI 命中数与标签字典序，**没有任何差异化目标函数**（`PLAN.md` §10 已记录为
未实现的承诺）。而且这些候选连车次都查不到（`exact_station_identity_not_found`），
链路走不到行程生成。

**所以现在这样用**：直接说目的地。推荐目的地这一半等能力 A 落地。

## 4. 一次完整使用

以「从武汉出发，去婺源待两天」为例——**明确目的地**的用法。

| # | 你做什么 | 预期看到什么 |
|---|---|---|
| 1 | 说出需求：出发地、**明确的目的地**、时间、几个人、预算、节奏、交通偏好 | 系统回一个待确认的意图；缺必填项会点名要（`pace` 与 `transport_preferences` 是必填） |
| 2 | 确认意图 | 任务开始跑，进入候选生成 |
| 3 | 等采集 | 逐步取回车次、目的地、景点；每项都带证据状态 |
| 4 | — | （明确目的地时无需选候选） |
| 5 | 等行程 | 逐日时间轴：跨城往返、当地交通、景点、餐食、住宿办理、缓冲 |
| 6 | 改一处约束（比如「第二天别那么赶」） | 生成**新版本**，旧版本仍在。新版本可用才会切过去 |

第 6 步是它和普通行程生成器的区别：改一处约束不是重新生成一份无关的行程，
是在同一个任务里出一个新版本，并且**新版本不可用时不会顶掉旧版本**。

## 4. 看到 unknown / 待确认，是设计不是故障

系统对每一条事实都标两件事：**这个值有多可靠**，以及**它有多新**。

你会看到这些词：

| 你看到 | 意思 |
|---|---|
| 已核实 | 有真实来源，且在时效窗内。这是唯一「我有把握」的说法 |
| 需要重查 | 有来源，但超过时效窗了，正在或即将重新查 |
| 存在分歧 | 两个来源说的不一样，需要你选一个 |
| 不知道 | 没查到，或者根本没有数据源 |

**下面三样目前一定是「不知道」，这是已知的、有意的：**

- **住宿价格**——高德 POI 不返回价格，系统里没有房价数据源。行程会给你住宿
  **片区**和候选酒店的名字位置，但不会有价格，预算里也不含房费。
- **景点开放时间**
- **景点门票价格**

看到这三样是 unknown，不是系统坏了，是它**拒绝编数字**。这三样请自己在出行
前确认一次。

**「待确认具体酒店」**同理：没选具体酒店时，首末段交通按住宿片区或交通枢纽估算，
选定之后会细化。

## 6. 出了问题怎么看

- **行程一直排不出来**：多半是某个域没采到。界面会列出缺哪一项与下一步动作。
- **目的地/当地交通一直「未采集」**：`AMAP_WEB_SERVICE_KEY` 没配或配错。
- **车次查不到**：12306 只放售一定时间窗内的车次，日期太远就查不到。
- **运行停止并提示「系统内部错误」**：这是程序 bug，不是数据问题，运行记录里
  有异常类型。

运行数据都在 `runtime/sessions/<run_id>/`，出问题时这个目录就是现场。

---

## 7. 当前不做的事

- **不订票、不订房。** 只做决策支持，给你可执行的行程和依据。
- **不猜。** 没有来源的数字不会出现。
- **不做消费级交互。** 修改重排目前靠改约束，不是拖拽。
