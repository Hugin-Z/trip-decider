# soak 发布前置：第八次复测两挂点修复的两轮验收

两轮 soak 都由审核方（不是修复方）在**修复后的工作区**上跑，用于复核
「20/20」这句自报。原始明细见同目录 `soak-r8-audit.json` 与
`soak-r9-audit.json`。

## 为什么留这两份

r8 交付自报「soak 20 轮 20/20」，但仓库里没有任何产物可复核——`--report`
是可选参数，不落盘就只剩一句话。此后 soak 作为发布前置，报告随轮存证。

## r8 轮（挂点一/二首次修复后）

| 项 | 值 |
| --- | --- |
| 轮数 | 20 |
| 失败 | 0 |
| 整轮耗时 | p50 21.3s / p90 34.3s / max 36.0s |
| 超时·失败事件 | 无 |
| 终态分布 | 17 × `NEED_USER_INPUT_OR_EVIDENCE`，3 × `NO_FEASIBLE_CANDIDATE` |

## r9 轮（R1/R2/R3 叠加后）

| 项 | 值 |
| --- | --- |
| 轮数 | 20 |
| 失败 | 0 |
| 整轮耗时 | p50 20.6s / p90 31.4s / max 40.5s |
| 超时·失败事件 | 无 |
| 分阶段 p50 | compare 20.6s（max 35.2s）、assemble 5.0s、verify 0.0s（max 12.0s） |

`NO_FEASIBLE_CANDIDATE` 不是失败——它是「这组种子在真实数据下确实没有可行
候选」的正常终态。这一点在 soak 首跑时曾被探针自己误判成失败，见
`4535c60` 的提交说明。

## 本轮 soak 探针自身的变更

`_synthetic_evidence` 从手写载荷改为**原样采用产品公布的 example**，与
「说明书必须能直接回喂」的元用例同源：说明书一旦和解析器分叉，soak 与元用例
会同时红。

留一条已知的软化点：新实现遇到非 Mapping 的 example 会返回 `None` 走
`continue`，也就是 example 退化成字符串时 soak 会**静默跳过**而不是失败。
这个方向由 `test_every_published_user_supply_example_is_directly_replayable`
守着（实测退化后 `SUBFAILED(action_id=...)`），不是覆盖洞，但 soak 单独
不再抓得到。
