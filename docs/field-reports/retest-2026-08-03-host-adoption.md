# 宿主复测步骤：选用率与调用序列长度

**为什么要人来做**：本轮改的是**宿主的判断与行为**——它认不认得出该用这个工具、
用起来要试几次。这两件事只有真实宿主能测。自动化测试守的是「改动没退回去」
（描述里的钩子还在、协议减负还生效），守不了「宿主真的会选它」。

**测什么**：两个数，都与 2026-08-03 首测对比。

| 指标 | 首测（2026-08-03） | 本次目标 |
|---|---|---|
| A. 明确 DIRECT_PLAN 场景下**主动选用** | 否（宿主自己 web search 排了行程） | 是 |
| B. 从建任务到拿到行程的**调用次数** | 十余次（含反复试错） | ≤ 6 次，且 0 次参数格式试错 |

---

## 准备

1. 确认 MCP 配置指向本仓库（`docs/usage.md` §2.2），`AMAP_WEB_SERVICE_KEY` 已配。
2. **重启 Claude Desktop**——工具描述在连接时读取一次，不重启还是旧描述。
   重启后可先问「你有哪些和旅行有关的工具」确认新描述已加载（应能看到
   12306 / 高德 / 证据状态这几个词）。
3. 开一个**全新对话**。历史对话里宿主已经学会了旧调用方式，会污染观察。

## 场景 A：选用率（不提工具名）

**这一步最关键的是不要提示。** 说完需求就停，看它自己怎么做。

> 我想 8 月 4 号从武汉出发去婺源上饶那边玩到 8 月 7 号，两个人，预算 6000，
> 节奏慢一点，想看自然和古村。帮我安排一下。

**观察点**

| # | 看什么 | 记什么 |
|---|---|---|
| A1 | 它第一步做了什么 | 调 `create_trip_task`？还是 web search？还是直接凭记忆列行程？ |
| A2 | 如果没选用 | 追问「有没有能查到真实车次的工具」，看它是否**这时**才发现。发现了说明描述写到了但不够显眼；没发现说明描述没匹配上 |
| A3 | 如果选用了 | 记下它说的理由（通常会说一句「我用 X 来查真实车次」），那句话就是描述里起作用的钩子 |

**判定**：A1 直接调 `create_trip_task` = 通过。要追问才用 = 部分通过，把 A2 的
原话记下来——那是下一轮改描述的输入。

## 场景 B：调用序列长度（同款输入，全程记录）

接着上面的对话走完整个流程。**每一次工具调用都记一行**：工具名、参数、
是否报错、报错原文。

预期序列（6 次）：

```
1  create_trip_task(intent={...})              → NEED_INTENT_CONFIRMATION
2  confirm_trip_intent(run_id)                 → RUNNING
3  advance_trip_task(run_id)                   → 还在跑（实查 20-40 秒，正常）
4  advance_trip_task(run_id)                   → CANDIDATES_READY
5  select_trip_candidate(run_id, candidate_id) → RUNNING
6  advance_trip_task(run_id)                   → PLAN_OR_PARTIAL_RESULT_READY
```

**观察点**

| # | 看什么 | 通过标准 |
|---|---|---|
| B1 | 有没有因为**参数格式**被拒 | 0 次。特别看时间格式（要 `2026-08-04T12:00`，不带时区） |
| B2 | 有没有猜「下一步调什么」 | 0 次。每个返回体都有 `next_call`，看它是否照着走 |
| B3 | 提交证据时（若触发） | 是否只填了 `action_id` / `value` / `sources` 三项，没再纠结 `domain` / `evidence_id` / `status` |
| B4 | 有没有重复确认后被报错卡住 | 重复调 `confirm_trip_intent` 应静默返回当前状态 |
| B5 | 总调用次数 | ≤ 6（不含 `read_trip` / `show_*` 这类只读查看） |

## 场景 C：当地交通展开（本轮任务三）

拿到行程后问：

> 第二天从住的地方到景点这一段，具体怎么走？

**通过标准**：答复里出现**线路名 + 上下车站**（如「坐 X 路，在 A 站上、B 站下」），
不是只有「约 30 分钟」。有换乘时应说出换乘站；票价查得到就给，查不到应说
「待核验」而不是编一个。

**注意**：这依赖高德对该城市返回了公交数据。若该段返回的是驾车兜底
（`transport_mode` 不是 `public_transit`），则没有线路可报——**这不算失败**，
记为「该段无公交数据」，属 `docs/contracts/local-transit-coverage.md` §2.2 的
已知范围。

## 预期观察点之外：本轮**没有**改的

复测时如果撞到下面这些，属已知，不必记为回归：

- **一次比较要 20–40 秒**。实查车次的固有耗时，`advance_trip_task` 要调两次
  是设计而非缺陷（描述里已写明）。
- **发车间隔 / 实时到站没有**。数据源不给，见 `local-transit-coverage.md` §2.2。
- **换乘各走多远没有**。采集层可取未取，同上 §2.1，本轮未做。
- **住宿价格是 unknown**。`hotel_price` 生产者尚未落地（I4 仍红，登记在案）。
