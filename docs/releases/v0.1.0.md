# trip-decider v0.1.0

`v0.1.0` is the first public engineering baseline for trip-decider. It is a local,
evidence-constrained travel decision prototype, not a consumer booking service or a
claim of universal destination coverage.

## Highlights

- **Evidence-constrained planning** — provider and user-supplied facts pass through
  field-level support/freshness evaluation and decision gates before the planner can
  rely on them.
- **Itinerary verification** — railway claims are checked individually and reported
  as `sourced`, `conflicting`, or `unknown`; an unsupported claim is not labelled false.
- **MCP integration** — an external MCP-capable LLM host can interpret conversation,
  call tools and advance the stateful runtime without becoming the source of facts.
- **Deterministic Web mode** — the standalone local Web entry extracts explicit trip
  fields with deterministic rules and does not require a model API.
- **Support × Freshness** — `sourced / estimated / conflicting / unknown` is evaluated
  separately from `fresh / stale / undated`; freshness is recomputed when data is read.
- **Stateful runtime** — intent confirmation, execution, blocking/recovery, installed
  PlanVersions and revisions are persisted as a resumable workflow.

## Verified scope

The principal end-to-end field-tested scenarios cover **Wuhan → Wuyuan/Shangrao**:

- Claude Desktop / MCP host adoption and task progression;
- live China Railway 12306 schedule/fare verification;
- AMap place, POI, route and local-transit collection in the exercised paths;
- repeated real-provider soak runs reaching explicit terminal outcomes.

The repository also records two audited 20-round soak runs with zero probe failures.
Those outcomes include `NEED_USER_INPUT_OR_EVIDENCE` and `NO_FEASIBLE_CANDIDATE`;
they do not mean that every round produced an itinerary. See
[`soak-2026-08-05-r8-r9-gate.md`](../field-reports/soak-2026-08-05-r8-r9-gate.md).

## Not supported

- autonomous ticket, hotel or attraction booking;
- complete real-time hotel price or inventory coverage;
- complete weather integration;
- universal destination or route coverage;
- a hosted, authenticated, multi-user consumer service;
- runtime persistence formats before v2.

Flight planning and long-distance road transport are not yet provided through the same
complete planning path as railway travel.

## Verification

### Offline CI

Every pull request and push to `main` is configured to install locked development
dependencies and run Ruff, Pyright and the complete deterministic pytest suite without
API credentials. The first GitHub-hosted run must pass before the release is tagged.

### Live smoke

`scripts/smoke_live.py` and `scripts/smoke_action_loop.py` are manual checks requiring
provider network access and an AMap Web Service key. They validate current external
integration behavior; they are intentionally separate from offline CI.

### Soak

`scripts/soak_full_loop.py` repeatedly exercises the real action loop under provider
timing and data variation. Soak is a release-confidence check, not a normal CI job and
not proof of future provider availability.

See [`docs/verification.md`](../verification.md) for the exact boundaries and commands,
and [`KNOWN_ISSUES.md`](../../KNOWN_ISSUES.md) for the public limitation inventory.
